# ブラウザー単独版

v0.3.0では、各利用者がHTMLをブラウザーで開き、そのブラウザー内で問題を生成できます。HTMLにはRustからビルドしたWebAssembly、画面のJavaScript、KaTeXと数式フォントを含めます。実行時のサーバー、インストール、アカウント、ネットワーク通信は不要です。

## 開き方と配布

GitHubの「Code → Download ZIP」からリポジトリを取得し、展開してから最上位の[index.html](../index.html)を開きます。単一HTML版の[browser/漸化式ラボ.html](../browser/漸化式ラボ.html)に移動します。GitHub上でHTMLのソースを表示するだけではアプリは起動しません。

|ファイル|使い方|
|---|---|
|`browser/漸化式ラボ.html`|1ファイルで動作します。別のPCへこのファイルだけを渡せます。|
|`browser/index.html`|分割した資産を使います。`browser`フォルダー全体を展開し、配置を保持します。|
|`index.html`|ダウンロードしたリポジトリから単一HTML版を開く入口です。単独では配布しません。|
|`dist/recurrence-lab-browser.zip`|ビルド時に作成する配布ZIPです。単一HTML、使い方、KaTeXライセンスを含みます。|

WebAssemblyとWeb Workerに対応した最新版のデスクトップ版Chrome、Edge、Firefoxを推奨します。実施したブラウザーテストは[検証記録](validation.md)を参照してください。スマートフォンやタブレットでは、端末のファイル管理やブラウザーによってローカルHTMLの開き方が異なります。画面幅に合わせた表示には対応しますが、すべての端末でローカルHTMLを実行できることを保証するものではありません。

## 問題を解く

難易度と型を選び、「新しい問題をつくる」を押します。総合演習では型を解答まで伏せます。「考え方のヒント」と「解答をたしかめる」は個別に開けます。28系統・75種類の登録構成から、係数などを変えて問題を生成します。

生成と確認はWeb Workerで実行します。候補数は200件まで、処理時間は10秒までです。「生成を中止する」では実行中のWorkerを終了します。新しい要求に失敗した場合や中止した場合も、すでに画面にある問題を保持します。

直近40件の問題IDを使って重複を避けます。ブラウザーのローカル保存機能を使える場合は次回もIDを保持します。ローカルファイルに対する保存を制限するブラウザーでは、開いている間だけ保持します。問題そのものはページを閉じると失われるため、後で解く問題はRecipeを保存してください。

## 保存と再現

「TeXを保存」でブラウザーからTeXファイルをダウンロードします。解答を閉じているときは問題のみ、開いているときは方針と解答も含めます。PDF化する場合は利用者のpLaTeXとdvipdfmxを使用します。PDF組版の実機確認は検証記録を参照してください。

詳細欄の「Recipeを保存」で構成をJSONとしてダウンロードします。「保存したRecipeから問題を再現」で読み込むと、登録構成との一致を検査し、同じ問題と解法を再構成します。読み込めるJSONは256 KiBまでです。任意のブロック編集や未登録の接続は受け付けません。

ブラウザー版が保存するRecipeの`seed`は、64ビット整数の精度を保つため10進文字列です。Rust＋Lean版で保存した数値形式の`seed`も、ファイルの元のJSONテキストをRust側で読み込むため丸めずに再現します。新規生成は数値コスト8以下の候補を採用します。保存済みの規則版1.0の重み付き総和Recipeは、この予算を超えてもブラウザー版で再現できます。再現時にも登録構成との一致と厳密計算による確認を行います。

## 数学的な確認

ブラウザー版も、ネイティブ版と共通のRustの生成器、厳密有理数計算、型付きProblemIRとDerivationIR、Recipe再現を使用します。候補を生成した後、次を確認します。

1. Recipeを再実行した問題・解法が表示内容と一致すること。
2. 一般項がすべての初期条件と一致すること。
3. 漸化式の開始添字から`n=20`まで、一般項がすべての漸化式を満たすこと。連立では両方の数列を確認します。
4. 同じ範囲で、登録した分母非零や正値の条件を満たすこと。

これらの計算には浮動小数点の近似を使いません。漸化式が`n+1`や`n+2`を参照する場合に備えて、一般項から22項目まで算出します。確認結果は問題に対応する内容ハッシュとともに表示します。

**この有限項の確認は、全添字の漸化式、一意性、全域の定義域条件を証明するものではありません。ブラウザーではLeanを実行しません。** 画面にはブラウザー内の確認として表示します。登録した28系統・75構成のLean検証や参照版との照合は、従来のRust＋Lean版で実施したもので、ブラウザーが生成する一問ごとの新たな形式証明とは区別します。

生成した一問ごとにLeanで全項を検証する場合は、[READMEのRust＋Lean版](../README.md#任意のrustlean版)を使用してください。

## 開発者向けビルド

Rust、Python 3.11以上と、固定版のwasm-bindgen CLIを使用します。

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.105 --locked
python3 scripts/build-browser.py
```

スクリプトは`cargo build --locked --release --lib --no-default-features --features browser --target wasm32-unknown-unknown`を実行し、同じ版のwasm-bindgenでWorker用コードを生成します。WebAssemblyをJavaScriptに埋め込むため、`file://`で開く際もWASM取得用のHTTP要求は発生しません。

`browser/`に分割版と単一HTML版、`dist/`に配布ZIPと`browser-manifest.json`を作成します。マニフェストには版、配布サイズ、ZIPとWASMのSHA-256を記録します。単一HTMLにはCSS、フォント、JavaScript、アイコン、KaTeXライセンスを埋め込みます。利用者にはビルドツールを配布する必要はありません。

通常テストとオフライン画面テスト:

```bash
cargo test --locked
cargo test --locked --features browser --lib
npm ci
npm run test:offline
```

画面テストにはビルド済みのブラウザー版とChromiumが必要です。`CHROMIUM_PATH`で実行ファイルを指定できます。検証の結果と確認範囲は[検証記録](validation.md)にまとめています。

開発環境の管理ポリシーが`file://`への移動を禁止する場合は、次の代替テストを使用できます。

```bash
RECURRENCE_TEST_STATIC_PREVIEW=1 npm run test:offline
```

代替テストは許可された`localhost`から単一HTMLを読み込み、生成前にブラウザーをオフラインにします。問題生成用のAPIサーバーは使用しません。この確認は、ローカルファイルを直接開く経路の動作確認とは区別します。
